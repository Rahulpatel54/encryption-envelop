1. Copy the files in

Drop the whole app/service/encryption/, app/models/security/, app/migrations/, app/controllers/encryption/, app/routes/encryption/, app/workers/ folders into your existing app/ (or src/) root, merging with whatever's already there. Don't overwrite existing models/index.js, routes/index.js, etc. — you're going to import into them, not replace them.

2. .env (or .env.example)

Add:

ENCRYPTION_KEY_PROVIDER=env
ENCRYPTION_KEK_VERSION=1
ENCRYPTION_KEK=<base64 32-byte key>
ENCRYPTION_ROTATION_BATCH_SIZE=500
ENCRYPTION_ROTATION_ATTEMPTS=3
ENCRYPTION_ROTATION_QUEUE_NAME=encryption-rotation
REDIS_URL=redis://127.0.0.1:6379

Generate a key once: node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"

3. Wherever your Sequelize models are loaded (usually models/index.js)

This is the file that does new Sequelize(...) and loops over model files. Add the two new models there so they get the same sequelize instance as everything else:

javascript
db.EncryptionKey = require('../app/models/security/encryption.key.model')(sequelize);
db.EncryptionRotation = require('../app/models/security/encryption.rotation.model')(sequelize);

If your project uses sequelize-cli auto-loading (reads every file in models/), just move/symlink those two model files into your real models/ folder instead — then this step is automatic.

4. Migrations folder

Copy the two migration files into your project's actual migrations/ directory (the one .sequelizerc or config/config.js points at), then:

npx sequelize-cli db:migrate
5. Register rotation targets — this is the file you'll actually edit most

app/service/encryption/rotation.targets.js is intentionally empty. Add your real models here, e.g. if you have a User model with an encrypted SSN column:

javascript
const { registerTarget } = require('./rotation.registry');
const { User, PaymentMethod } = require('../../../models'); // your existing models/index.js export

registerTarget('users.ssn', {
  model: User,
  primaryKey: 'id',
  encryptedFields: ['ssn_encrypted'],
});

This file must be required once at startup, after models are loaded (see step 7).

6. Wherever you construct your Express app (app.js, server.js, or bootstrap.js)

Wherever you currently do app.use('/something', someRoutes):

javascript
const { buildEncryptionRoutes } = require('./app/routes/encryption/encryption.routes');
const { RotationService } = require('./app/service/encryption/rotation.service');

const rotationService = new RotationService({
  RotationModel: db.EncryptionRotation, // from step 3
  io, // your existing Socket.IO server instance
});

app.use('/encryption', buildEncryptionRoutes({
  rotationService,
  authorize: yourExistingCasbinMiddleware('encryption:rotate'), // your real authz middleware
}));
7. Wherever you create your Socket.IO server

Right after const io = new Server(httpServer, ...):

javascript
const { initRotationSocket } = require('./app/service/encryption/rotation.socket');
initRotationSocket(io);
8. Worker process — new file, e.g. worker.js at project root

This runs separately from your API process (own pm2/Docker entry, own node worker.js):

javascript
require('dotenv').config();
const db = require('./models'); // your existing models/index.js — gives you sequelize + all models
require('./app/service/encryption/rotation.targets'); // step 5 registrations run here
const { KeyService } = require('./app/service/encryption/key.service');
const { EncryptionService } = require('./app/service/encryption/encryption.service');
const { createRotationWorker } = require('./app/workers/encryption.rotation.worker');

const keyService = new KeyService({ EncryptionKeyModel: db.EncryptionKey });
const encryptionService = new EncryptionService({ keyService });

createRotationWorker({
  sequelize: db.sequelize,
  RotationModel: db.EncryptionRotation,
  encryptionService,
  keyService,
});

console.log('Encryption rotation worker started');

Add a script for it in package.json:

json
"scripts": {
  "worker:rotation": "node worker.js"
}

### Key architectural facts to remember
- **Envelope format**: `"v1:" + base64(JSON)` containing `kekProvider`, `kekVersion`, `wrappedDek`, `wrapIv`, `wrapTag`, `iv`, `tag`, `ciphertext`. Self-describing — decrypt() reads `kekVersion` from the envelope itself.
- **AAD convention** (critical, must stay consistent everywhere): `` `${record.constructor.name}:${field}:${primaryKeyValue}` `` — used in worker's DEK rotation. Any code that encrypts fields outside the worker must use this exact same AAD format or decryption breaks.
- **Rotation types**: `KEK_REWRAP` (only rewraps the wrapped DEK, ciphertext untouched) vs `DEK_ROTATION` (full decrypt/re-encrypt with fresh DEK). Both use cursor pagination (`WHERE id > lastId ORDER BY id LIMIT batchSize`), bounded per-batch transactions, Postgres advisory lock (`pg_try_advisory_lock(hashtext(type:target))`) to prevent concurrent conflicting rotations on the same target.
- **Rotation targets are never auto-discovered** — must be explicitly registered via `registerTarget()` in `rotation.targets.js`. **This file is currently empty — nothing is registered yet for the real production models.**
- **Never destroys/retires KEK automatically** — `keyService.retireKey()` must be called manually after confirming no data depends on the old version.

3. **Worker shape**: Codebase's `app/workers/index.js` expects singleton objects with `.start()/.stop()/.isRunning()/.getWorker()` (see `EmailWorker` pattern). Rewrote `encryption.rotation.worker.js` as a class (`EncryptionRotationWorker`) with a `.configure({sequelize, RotationModel, encryptionService, keyService})` method called once at startup before `.start()`, matching that convention. Needs to be added to the `workers` array in `app/workers/index.js` (shown, not yet confirmed applied by user).
4. **Sequelize model style**: Codebase uses `sequelize.define(tableName, attrs, options)` with `(sequelize, Sequelize) => {...}` signature — NOT `class extends Model` / `Model.init()`. Both security models rewritten to match.
5. **Socket.IO**: Existing `socket.js` (`attachSockets`) uses default namespace with mandatory `userId` handshake auth, disconnecting unauthenticated sockets. Rotation sockets deliberately use a **separate namespace** (`/encryption-rotations`) via `io.of(...)` to avoid that auth requirement — **flagged as a decision needing explicit sign-off**: rotation progress currently has NO auth/room-join restriction. Call `initRotationSocket(io)` in `app.js` right after `socketServer(app, server, corsOptions)` returns `io`.
